# repository-layout.md — recibir

この文書が持つのは 2 つだけである。**署名検証テストの必須観点**と、**公開前に確かめること**。

**リポジトリの構成は書かない。** パッケージ構成は `CLAUDE.md`「パッケージ構成」が正本である。
名前に layout が入っているのは、この文書が最初に参照された時点の呼び名であって、
中身を決めるものではない。

**何が揃っていれば完成かは [SPEC.md](SPEC.md) §7 が持つ。** ここが持つのは、それをどう確かめるかである。

## 署名検証テストの必須観点

`SendGridSignatureVerifier` のテストは、以下をすべて持つこと。
`CLAUDE.md`「テスト方針」が求める「他のどこよりも厚く」の厚さは、この一覧で測る。

**設計の正本は [SPEC.md](SPEC.md) §4.1 である。** 観点はそこから導いた。
各行の右列は、その観点が §4.1 の何を守っているかを示す。

| # | 観点 | 何を守るか |
|---|---|---|
| 1 | 正しい署名と正しい timestamp で `true` を返す | 基本形。これが通らないと以下は意味を持たない |
| 2 | ボディを 1 バイトだけ変えると `false` | 検証対象が生ボディであること |
| 3 | **ボディを JSON としてパースし、再シリアライズすると `false`** | **生バイト列でなければならない理由**（下記） |
| 4 | timestamp だけを変えると `false` | 検証対象が `timestamp \|\| rawBody` であること |
| 5 | timestamp とボディの連結順を逆にすると `false` | 同上。連結の向き |
| 6 | timestamp が 10 分より古いと `false` | リプレイ対策の窓（過去方向） |
| 7 | timestamp が 10 分より未来だと `false` | 同（未来方向）。**片側だけ見ると通り抜ける** |
| 8 | 別の鍵ペアで署名したものが `false` | 公開鍵の照合が効いていること |
| 9 | 公開鍵が不正な Base64 のとき `false`。**例外を投げない** | 失敗理由を返さない（§4.1） |
| 10 | 署名が不正な DER のとき `false`。**例外を投げない** | 同 |
| 11 | timestamp が数値として解釈できないとき `false`。**例外を投げない** | 同 |
| 12 | 空のボディ・空の署名・空の timestamp で `false`。**例外を投げない** | 同。**境界で例外が漏れやすい** |
| 13 | 戻り値・例外・メッセージのどれからも失敗理由が読めない | §4.1「すべて `false` に倒す」 |
| 14 | BouncyCastle を classpath に置かずに全テストが通る | §4.1「外部依存なし」 |
| 15 | SendGrid アカウント・ネットワーク・DB なしで全テストが通る | §6、`CLAUDE.md`「テスト方針」 |

### 3 を落とせない理由

**受信したボディを JSON へパースして書き戻すと、バイト列が変わる。** 空白の位置、
キーの順序、数値やエスケープの表記——どれも JSON として等価だが、署名の入力としては別物になる。

**素朴に実装すると、この経路を踏む。** ボディを DTO で受け取るほうが Spring では自然で、
そのとき署名検証は必ず失敗する。原因が分かりにくいので、`CLAUDE.md`「絶対に変更しないこと」2 は
**`ByteArray` で受けること**を明記している。

**テストとして残す意味はここにある。** 「なぜ `ByteArray` なのか」を、
文章ではなく落ちるテストで示す。

### 観点を足すとき

**足した観点は、右列に「§4.1 の何を守るか」を書けること。** 書けないなら、
それは §4.1 に無い要求である——**先に設計の側を決める。**

## 公開前に確かめること

[SPEC.md](SPEC.md) §7 が「何が揃っていれば完成か」を持つ。ここはその確かめ方である。
**§7 の項目をここへ写さない。**

### 履歴（`CLAUDE.md`「作業の型」の関門）

**public リポジトリで、コミット履歴も公開物である。** 消しても履歴には残る。

- [ ] `git log -p` の全体に API キーが含まれていない（`SG.` で始まる文字列を探す）
- [ ] 実在するメールアドレスが含まれていない（テストの入力を含む）
- [ ] 顧客名・取引先名が含まれていない
- [ ] `.env` に類するファイルが一度も add されていない
- [ ] 手元固有の絶対パスが含まれていない

**混入を見つけたら、削除では済まない。** 資格情報は無効化する。

### テストが外部なしで通ること

- [ ] SendGrid アカウントを持たない環境で `./gradlew build` が通る
- [ ] ネットワークを切った状態でテストが通る（codegen 済みの前提で）
- [ ] 検証をスキップする経路が無い（プロファイル・環境変数・プロパティのいずれでも）

### 文書

- [ ] `README.md` の「動かす」の手順が、その順序で実際に通る
- [ ] 存在しないファイルや節を指している参照が無い（`git grep` で洗う）
- [ ] 数字に測定日が付いている
